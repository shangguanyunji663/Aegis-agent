# Aegis 第六轮：回复「真人化」改造

> 分支:`fix/source-labels` · 时间:2026-08 · 系列:[REFACTORING](REFACTORING.md) → [OPTIMIZATION](OPTIMIZATION.md) → [AUTH-MYSQL](AUTH-MYSQL.md) → [LANGGRAPH-DOCKER](LANGGRAPH-DOCKER.md) → [DEEP-ENHANCEMENTS](DEEP-ENHANCEMENTS.md) → 本篇
> 性质:**回复「真人化」改造——提示词重写 + 兜底模板防泄漏修复 + 429 指数退避重试**
> 验证:`pytest 65/65` · 界面实测（GLM 可用时自然口语化，429 限流时兜底模板不露馅）· 新增 429 指数退避重试

***

## 1. 背景

用户反馈"顺着AI的话往下说时AI的回复太假"，实际测试发现：
- LLM 可用时（GLM 未限流）回复自然口语化，但提示词模板僵硬（自称"咨询回复生成器"、强制"共情+步骤+提问"三段式）；
- GLM 免费 API 429 限流时静默降级到兜底模板，但旧版模板直接粘贴内部记忆（"用户提到：X；系统回应重点：Y"），且没有重试机制；
- 兜底模板开场/收尾千篇一律，不区分陪伴/咨询/研究等意图，导致"顺着往下说就变假"。

本轮目标：让回复像真人——LLM 可用时自然口语，429 限流时兜底模板不露馅、按意图区分话术，并给 429 加指数退避重试。

---

## 2. 问题诊断

### 2.1 提示词模板僵硬（LLM 可用时）
- 系统提示词自称"咨询回复生成器"，用户问"你是谁"会被复读，还会被写进记忆反复回响；
- 用户提示词强制"先共情→1-3个步骤→开放问题"三段式，导致每条回复都是共情+编号列表+提问的八股文；
- 温度固定 0.2，输出呆板。

### 2.2 兜底模板泄漏内部记忆（429 限流时）
- `_fallback_answer` 把 `app/rag/memory.py` 的内部格式"用户提到：X；系统回应重点：Y"整行粘贴进用户可见回复；
- 开场/收尾不区分意图：COMPANION 也问"最难受的时刻发生在什么时候"，显得机械；
- 降级时没有日志，无法定位 LLM 失败原因。

### 2.3 429 限流无重试
- `post_json` 遇到 429 直接返回空字典，静默降级，没有指数退避重试。

---

## 3. 逐项变更

### 3.1 重写 `app/llm/prompts.py`（自然人设+灵活对话风格+防内部标签泄漏）
- 系统提示词：
  - 身份改为"你是 Aegis，校园心理支持助手"，口语化、像真人陪伴者；
  - 保留安全边界（不诊断/不承诺保密/不泄露内部风险分与审计细节）；
  - 说话方式指导：贴着对方的话说、口语短句、回复长短匹配用户消息、不强制编号列表、不必每条以提问收尾、一次最多问一个问题、建议最多两条且只在合适时给。
- 用户提示词：
  - 保留现有字段（用户消息/历史摘要/路由意图/风险等级/可引用知识/可用稳定练习/标准回复 Skill）；
  - 加防泄漏指示：历史摘要等字段仅内部参考，回复中禁止出现"用户提到""系统回应重点"等标签字样，不得逐字复述。

### 3.2 修复 `app/agents/classic.py` 兜底模板
- 新增 `_user_focus_from_memory` 工具函数，从记忆行提取用户原话（去掉"用户提到：/；系统回应重点："等内部标签）；
- `_fallback_answer`：
  - 删除整行粘贴记忆原文的写法，改为自然引用用户原话（如"你之前提到「…」"）；
  - 开场/收尾按意图区分：COMPANION 用简短口语回应（不再追问"最难受的时刻"）；HIGH 风险安全话术原样不动；
  - `finalize_plan` 降级时加 `logger.warning`（provider/model），便于排查 LLM 间歇失败。
- 修复 `compose_plan` 的 `mode` 语义回归（从"final"改回语义值：support/research_support/safety_template）。

### 3.3 `app/config.py` + `app/llm/client.py` 增加 429 指数退避重试
- Settings 新增 `llm_support_temperature: float = 0.6`（偏高更像真人）；
- `post_json`/`post_json_stream`/`post_ndjson_stream` 加重试逻辑：
  - 429/5xx/超时值得重试，其余（401/403/JSON 解析）不重试；
  - 指数退避：首次 2s，第二次 4s，最多 2 次；
  - 流式请求在连接建立阶段重试，一旦开始接收 delta 则不再重试（用户已看到部分内容）。

### 3.4 测试同步
- `test_orchestrator.py:315` 改断言新开场白（"谢谢你愿意跟我说这些"）；
- 新增 `test_reply_style.py` 守护测试：
  - `build_messages` 不含"咨询回复生成器"且含防复读指示；
  - 兜底回复不含"用户提到"/"系统回应重点"；
- 全量测试 65/65 通过。

## 4. 验证记录

### 4.1 界面实测（GLM 可用时）
- 第1轮闲聊："太好了，阳光确实能让人心情变好不少。你想聊聊什么？"
- 第2轮倾诉："这确实挺让人难受的。明明外面天气那么好，心里却堵得慌，这种感觉肯定不好受。你是跟室友发生了什么具体的事吗？"
- 第7轮新会话："你好呀。我是 Aegis，校园里的心理支持助手。今天想聊聊什么？或者有什么想说的吗？"
- 回复自然口语化，无内部标签泄漏，不强制三段式。

### 4.2 界面实测（429 限流时）
- 第3-6轮（LLM 失败）：
  - 开场/收尾按意图区分（COMPANION 不再问"最难受的时刻"）；
  - 记忆引用自然（"你之前提到「…」"），无"用户提到/系统回应重点"内部标签；
  - 没有内部元数据泄漏。
- 429 重试逻辑已加，限流恢复后 LLM 可正常调用。

## 6. 遗留与建议
- GLM 免费 API 429 限流仍会影响体验，后续可考虑：
  - 切换到更稳定的 API（如 Ollama 本地部署）；
  - 在配置中增加 LLM 超时/重试次数上限；
  - 给用户提示"当前网络有点忙，请稍后再试"的友好反馈。
- 提示词可进一步优化：根据用户消息长度动态调整回复长度，避免闲聊时过长。
